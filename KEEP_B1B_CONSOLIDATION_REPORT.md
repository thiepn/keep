## Result

**IMPLEMENTED (local source), NOT RELEASE-CERTIFIED.** This is a substantial feature-first consolidation batch. KEEP's native daily home now contains a source-aware board of notes, anchored Markdown tasks, legacy favorites, manual external references and typed relationships. Its developer-only V2.1 resource demonstration now displays the actual saved note collection rather than hard-coded fabricated records. External provider adapters are deliberately *not connected*. A real browser session could not be tested in the source-only environment because dependencies were unavailable.

## Features delivered

1. **Owner-typed resource IDs:** `src/pkm/integration/ownerResourceRefs.ts` defines the versioned `thiepn://<product>/<module>/<kind>/<encoded-id>?v=1` pointer contract; source/kind validation, round-trip parsing, Unicode/percent-encoding protection and safe source landing routes. KEEP's local scheme and non-Folio adapters are **internal proposed handles**, not certified accepted deep links in external apps. Original owner IDs are retained unchanged. URI possession confers no access.
2. **Registered adapters:** `src/pkm/integration/sourceOwnerAdapters.ts` declares source adapters for KEEP, Folio, standalone Calendar, Habits, Vault and Hub. KEEP resolves its actual local notes/tasks. Every external adapter returns `not-connected`, null resource, no write, no live sync and requires owner consent; a Folio or Hub landing route, if available, is never constructed with private record IDs. A bounded, device-only KEEP Hub *draft* summary requires an unlocked vault and **is not published**.
3. **Legacy reconciliation:** `src/pkm/integration/keepResourceSpine.ts` combines original `note.pinned` and `note.isFavorite` flags with the existing global favorite preference list, deduplicates matching native IDs, re-resolves titles and lifecycle status from original notes, flags trashed/archived/locked/missing entries and preserves incompatible legacy shortcuts as clearly unresolved rather than deleting them. No second note/task store or ID migration.
4. **Stable Markdown task pins:** Native tasks with a unique `^block-id` remain linkable after moving a line. For unanchored tasks, the existing note-save callback adds a unique `^keep-...` anchor to the exact verified Markdown source line **before** writing the favorite. Stale/locked/trashed sources fail rather than guessing. Existing checklist tasks are explicitly not modified until their stable-identity protocol is certified. Duplicate anchors fail closed.
5. **Visible editable daily UI:** `src/components/home/KeepResourceBoard.tsx` provides pinned resources, Pin/Unpin, a native note/task picker, user-entered external owner references, copyable URIs, status badges, source routing only when safe, and one-note-to-other-resource relationships. Source navigation works within the normal KEEP shell; external references are marked not connected. `KeepTodayOverview.tsx` presents this once, without a duplicate pinned-note panel. Locked vaults never render this board.
6. **Actual note-line navigation:** `src/WorkspaceContext.tsx` now passes `options.viewState` to the tab engine; previously it was silently dropped. The original `WorkspacePaneSurface` passes the task line to `NoteWorkspaceView`, which focuses the relevant note position when available. Existing tab identity and note editing remain unchanged.
7. **Declarative links:** `src/pkm/integration/resourceLinks.ts` uses KEEP's existing preference service for bounded, validated relation *metadata* only; no shadow resource contents, automatic remote reads or writes. Relations can be added/removed; source notes and linked target notes are opened from the board. Missing targets remain visible and non-actionable.
8. **Personalization portability:** `favoritesManager` now recognizes owner-specific URI identity while preserving the legacy item API and key. The existing V1.6 config export/import now explicitly carries favorites and optional resource links, validates them and merges idempotently without altering source records. Older bundles remain accepted. Note that preference metadata is currently device-local best-effort; the existing code's scope name `global-synced` does not demonstrate actual cross-device synchronization.
9. **Misleading prototype cleanup:** `V2UnifiedExperienceView` no longer embeds fictitious Project Antigravity, Dr. Sarah Chen or mock due tasks: it reads real KEEP notes. Other V2.21/V2.22 in-memory prototype UIs are clearly labeled as **not persistent or authoritative**, preserving their experimental code while preventing confusion with real user data.
10. **Reproducible regression gate:** `npm run test:b1b` compiles its pure TypeScript model dependencies into an isolated OS temporary directory and runs 22 deterministic owner/ref/pinning/import/export tests. It is invoked by the existing `npm test` script after the native TSX suite when dependencies are available; no production changes.

## Remaining architectural risks and implementation handoff

- **Account and storage isolation:** global personalization preferences are currently a browser-local convenience, not a verified account-scoped encrypted store. Avoid putting sensitive information into manually supplied external display titles on shared devices. Test localStorage quota errors and cross-tab updates; move metadata to a consented, owner-isolated store only after an explicit backup/restore contract.
- **External identity and data access:** external resource IDs entered in the UI are asserted by users, **not verified** by external owners. Implement read contracts and permission/version checks in each source application before claiming active availability, inline mutation, history or bidirectional syncing. Missing source URLs are intentionally not guessed. Folio/Calendar PRs cannot be silently treated as merged or deployed.
- **Markdown task anchors:** native Markdown tasks have real source identity only with a unique anchor, and the source may change concurrently between reading and saving; the source-save path needs durable optimistic revision checks under sync races. Native checklists must retain their own original item IDs. Editor task-line focus is coded but requires actual React/browser verification on existing and new tabs.
- **Legacy favorites and cross-domain content:** a historical project/dashboard shortcut with no owner URI stays unresolved rather than being matched on title. Links and pins carry pointers, not destination data. No automatic deletion of orphaned references.
- **V2 domain engines:** V2.21 and V2.22 are separate in-memory model sandboxes, and B1b only labels their status; they are not integrated with canonical notes, Folio tasks, Calendar or Habits. They must not underpin daily user experience until genuine source ownership is established.
- **Hub integration:** the KEEP Hub summary is a bounded **device-only draft** with no raw titles, bodies, IDs or private links and no transport. Proper THIEPN Account authorization, consent, lock/account-change revocation and source-owned publication are future work.
