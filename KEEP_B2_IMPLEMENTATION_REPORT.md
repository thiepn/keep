Results are capped to 250 visible rows with honest count and a refine instruction.
2. **Actual source-backed planning contexts** (`src/pkm/integration/keepDiscoveryModel.ts`, `src/pkm/planning/planningService.ts`, `src/pkm/planning/planningNoteClassifier.ts`): project/goal/area identity remains the underlying canonical note ID. Reuses existing P49 goals/projects/areas relation and progress projection, including real project due date, status, priority and next original task. No second data engine or project database. The note classification function is shared with P49 instead of being copied.
3. **Unified discovery across knowledge and work** (`keepDiscoveryModel.ts`): existing KEEP notes, tasks, project/goal/area types with safe lifecycle filtering; no locked, archived or trashed note bodies are indexed. Tokenized multiword search combines original titles, safe previews and tags. Original task-source line is retained for navigation. Tasks without persistent anchors are **not** assigned invented canonical URIs.
4. **Source-informed relationships and context** (`keepDiscoveryModel.ts`, `resourceLinks.ts` existing, `indexer.ts` existing): user-created owner-URI links work in either direction; project-to-goal/area, goal-to-project and area membership are derived from original planner; existing linked-note IDs and verified Wikilinks/backlinks are derived using KEEP's existing vault index. Changed/stale source revisions are rejected. Original note URI and typed planning URI for the same note are treated as compatible context aliases. Missing and externally owned references remain inspectable, unavailable or explicitly not connected.
5. **Reusable saved views without new persistence** (`KeepKnowledgeExplorer.tsx`, `src/pkm/personalization/savedViewsManager.ts`): evaluates existing native Notes, Tasks and Projects Saved View filters against original KEEP records. External domains, e.g. Library, return an explicit unsupported result. Users can save a scoped query as an existing `SavedViewConfig`, select/delete custom views and pin a view through existing favorites. Existing note/task pins remain untouched.
6. **Portable identity repair** (`savedViewsManager.ts`, `src/pkm/personalization/configExportImport.ts`, `keepResourceSpine.ts`, `ownerResourceRefs.ts`): new custom-view IDs use UUID rather than millisecond collision-prone timestamps; imported `sv-custom-*` views preserve original IDs and reject duplicate/conflicting ones rather than replacing them. Config exports include custom view IDs. The same canonical owner-URI resolver now handles KEEP project, goal, area, and saved view references; pinned saved views from Today open the real view.
7. **Meaningful in-place task action** (`keepDiscoveryModel.ts`, `KeepKnowledgeExplorer.tsx`): complete a current original Markdown task through the existing source task mutator and caller's original note-save callback. Exact source line, real note ID, unique anchor and privacy status are checked before mutation; no guessed/fuzzy fallback. Native checklist task text is visible and opens its original editor, but cannot be mutated using a speculative line or duplicate label.
8. **Non-destructive navigation and privacy**: user keeps existing Vault, Notes, Folio, Calendar, Habits and Hub records and identifiers. External adapters remain unconnected from B1b. No new cloud sync, assumed owner grants, tab publishing or shadow copies. Open/locked state hides discovery data.
